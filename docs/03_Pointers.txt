Q4: int *p = NULL;
    printf("%d\n", *p);
Ans ✅ It is undefined behavior. In practice, it often causes a segmentation fault (or HardFault on an MCU).
Why?  In C, it's essentially   p = 0; So the pointer contains address: 0x00000000
      *p ==> "Go to address 0x00000000 and read an int."
      On a typical desktop OS: Address 0x00000000
                                            ↑
                                        Access denied
    The operating system protects this memory, so the program usually crashes with a segmentation fault.

    On an STM32 Microcontroller , Address 0x00000000 is not necessarily invalid.It often maps to: Flash memory, The vector table (Reset Handler, ISR addresses), 
    Boot memory (depending on configuration) . So it may lead to, read some unexpected value, or trigger a HardFault, or  behave differently depending on the memory map.

    This is why the C standard simply says: Dereferencing a NULL pointer is undefined behavior. It deliberately does not promise what will happen.
    Rule to Remember : Always check before dereferencing if a pointer might be NULL.

Q5: in int *p,  What does p++ do ?
    The compiler sees that p is an int *.
    "How big is one int?" .sizeof(int) = 4 bytes
    so compiler generates its code equivlent to New Address = Old Address + sizeof(pointed_type)
    So p now points to the next integer, not the next byte.
    This is why pointer arithmetic is called scaled arithmetic.

Q6: Why does p++ move by 1 byte for a char *, but q++ moves by 4 bytes for an int *?
    Pointer arithmetic is scaled by the size of the data type it points to. When we increment a pointer, the compiler adds sizeof(pointed_type) 
    bytes to the stored address so that the pointer points to the next object of that type.
    Simpler---> p++ moves the pointer to the next element, not the next byte. The distance moved is sizeof(*p) bytes

    | Pointer Type | `sizeof(*pointer)` | `pointer++` moves by |
    | ------------ | ------------------ | -------------------- |
    | `char *`     | 1                  | 1 byte               |
    | `short *`    | 2                  | 2 bytes              |
    | `int *`      | 4                  | 4 bytes              |
    | `float *`    | 4                  | 4 bytes              |
    | `double *`   | 8                  | 8 bytes              |

Q12. Why doesn't sizeof(arr) decay?
Ans: Because sizeof is a compile-time operator that needs the complete type. If arrays always decayed to pointers, 
    the compiler would lose the array length information and could never compute the array's total size. Preserving 
    the array type inside sizeof makes the operator useful and efficient. So designers made it an exception.

Q20. Does C support pass-by-reference?
Ans  No. C only supports pass-by-value. When a pointer is passed to a function, the pointer itself is passed by value (a copy of the address). 
        This allows the function to modify the object being pointed to, but not the caller's pointer variable. To modify the caller's pointer, 
        you must pass a pointer to the pointer (int **).
        Any object can be modified if you have its address and you have permission to write to it.

Q29. Why doesn't this swap the caller's pointers?
        void swap(int *a, int *b)
        {
            int *temp = a;
            a = b;
            b = temp;
        }

        "The parameters a and b are local copies of the caller's pointer variables. Swapping these local copies does not modify the caller's pointers. 
        To modify the caller's pointer variables, we must pass their addresses (int **) and swap *a and *b."
